# account 도메인

오픈뱅킹 연결과 계좌·잔액을 다룬다. 이체가 어느 계좌에서 나가는지를 여기서 정한다.

도메인 전반의 불변식은 [docs/domain-guide.md](../../../../../../../docs/domain-guide.md), 파트 간 계약은 [docs/integration-spec.md](../../../../../../../docs/integration-spec.md)가 기준이다. 이 문서는 패키지 내부 관점의 보충 설명이다.

## 책임

| 클래스 | 역할 |
|---|---|
| `OpenBankingConnectService` | 오픈뱅킹 인증 시작·콜백 처리, 계좌 최초 등록 |
| `OAuthStateStore` | 5분·1회용 state 보관과 대조 |
| `AccountService` | 계좌 목록, 기본 계좌 지정, 별칭 변경, 연결 해제 |
| `BalanceInquiryService` | 잔액 실시간 조회와 스냅샷 기록 |
| `BalanceInquiryPort` | 잔액 조회 경계. 실 오픈뱅킹과 Mock 대역이 갈라지는 지점 |

## 지켜야 할 것

### 계좌 연결 해제는 행을 지우지 않는다

`DELETE /api/accounts/{accountId}`는 `is_active`만 내린다. `transactions.account_id`와
`transfers.from_account_id`가 계좌를 FK로 참조하므로, 행을 지우면 **지난 이체를 되짚을 근거가
사라진다.** 분쟁이 났을 때 "누가 언제 어느 계좌에서 보냈는지"를 답할 수 없게 된다.

목록 조회가 `findAllByUserIdAndActiveTrueOrderByPrimaryDescIdAsc`로 활성 계좌만 읽으므로,
비활성으로 내리는 것만으로 목록·잔액조회·이체 대상에서 모두 빠진다.

### 해제할 수 없는 두 가지 경우

- **보내는 중인 이체가 걸린 계좌** — `PENDING`·`RISK_REVIEW` 이체가 있으면 `ACCOUNT_4005`로
  거절한다. 결과가 정해지지 않은 돈을 어디에도 귀속시킬 수 없다.
- **이미 해제한 계좌** — `ACCOUNT_4002`. 두 번 눌러도 상태가 흔들리지 않게 한다.

마지막 계좌를 해제하는 것은 막지 않는다. 계좌를 모두 끊는 것은 사용자의 선택이다.

### 기본 계좌는 비워 두지 않는다

기본 계좌를 해제하면 남은 계좌 중 첫 번째를 기본으로 올린다. 기본 계좌가 비면 계좌를 지정하지
않은 음성 명령("잔액 알려줘", "엄마한테 오만원 보내줘")이 **어느 계좌를 쓸지 알 수 없어진다.**
화면을 보지 않는 사용자에게는 이 상태를 알아차릴 방법도 없다.

### 연결과 잔액은 따로 껐다 켠다

오픈뱅킹 **잔액조회 API는 사업자 등록을 마친 이용기관에만 열린다.** 계좌 연결(인증)까지는
샌드박스로 진행할 수 있어도 잔액은 받아올 수 없다. 그래서 스위치를 둘로 나눴다.

오픈뱅킹 **잔액조회와 출금이체 API는 사업자 등록을 마친 이용기관에만 열린다.** 계좌 연결(인증)
까지는 샌드박스로 진행할 수 있어도 잔액과 이체는 쓸 수 없다. 그래서 스위치를 셋으로 나눴다.

| 설정 | 대상 | 기본값 |
|---|---|---|
| `movi.openbanking.mode` | 인증·계좌목록 | `mock` |
| `movi.openbanking.balance-mode` | 잔액조회 | `mock` |
| `movi.openbanking.transfer-mode` | 출금이체 | `mock` |

연결만 `real`, 잔액·이체는 `mock` 조합이 이 때문에 필요하다.

**셋 다 기본값이 `mock`이다.** 실 API 가 기본이면 설정을 빠뜨린 환경에서 진짜 돈이 나간다.
안전한 쪽이 기본이어야 한다.

`transfer-mode=real`은 `mode=real`을 함께 요구한다. Mock 인증으로 받은 토큰으로는 실제 이체를
보낼 수 없으니, 잘못 조합한 설정으로 조용히 대역 이체를 실행하는 것보다 기동 시점에 멈추는
편이 안전하다.

### Mock 잔액은 계좌마다 다르고, 이체하면 줄어든다

Mock 오픈뱅킹이 아는 계좌는 그쪽 잔액을 그대로 읽는다. Mock이 모르는 계좌(실제로 연결된
계좌)는 `MockTransferLedger`가 잔액을 들고 간다. **대역 이체도 이 장부를 깎으므로 어느 쪽이든
보내고 나면 잔액이 줄어든다** — 보내고 잔액을 다시 묻는 동선에서 금액이 그대로면 사용자는
이체가 안 된 것으로 듣는다.

장부는 메모리에만 있어 재기동하면 처음 금액으로 돌아간다. 시연·개발용 대역이다.

처음 보는 계좌의 금액은 핀테크이용번호에서 만든다. 두 가지를 지킨다.

- **계좌마다 다르다** — 모두 같은 금액이면 계좌를 골라 봐야 구분이 되지 않는다.
- **같은 계좌면 항상 같다** — 물을 때마다 달라지면 이체 한도·잔액 검증이 통과했다 실패했다 한다.

금액은 만원 단위로만 만든다. TTS가 "12만원"처럼 읽기 좋고 자잘한 끝자리가 남지 않는다.

### 잔액조회 실패를 0원으로 읽지 않는다

오픈뱅킹은 실패 응답에도 금액 필드를 0으로 채워 보낸다. 이를 그대로 읽으면 사용자가 **"잔액이
없다"고 믿게 된다.** 실패는 `ACCOUNT_5001`로 명확히 구분한다.

## 변경 이력

- **2026-09-01** — 계좌 연결 해제(`DELETE /api/accounts/{accountId}`)를 추가했다. soft delete,
  진행 중 이체 차단(`ACCOUNT_4005`), 기본 계좌 자동 승격. 응답은 해제 후 남은 계좌 목록이라
  화면이 다시 조회하지 않아도 된다.
- **2026-09-01** — Mock 잔액이 계좌마다 달라지게 했다. 이전에는 Mock이 모르는 계좌가 모두
  530,000원을 반환해 계좌를 구분할 수 없었다.
- **2026-09-01** — 출금이체를 `movi.openbanking.transfer-mode`로 따로 갈랐다. 이체 API 도 사업자
  등록이 필요해 "연결 real + 이체 mock" 조합이 필요했는데, 그전에는 `mode` 하나가 인증·계좌목록·
  이체를 함께 제어해 불가능했다. `OpenBankingTransferPort`를 새 경계로 두고, Mock 이 모르는
  계좌의 잔액·멱등성은 `MockTransferLedger`가 맡는다.
